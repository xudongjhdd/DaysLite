# DaysLite iOS 设计规格

日期：2026-08-06

## 1. 项目目标

在现有 DaysLite 仓库中新增一个独立的原生 iOS 应用，完整复刻 Android 版的产品功能，同时采用符合 iPhone 使用习惯的原生交互。应用需要具备真实提交 App Store 的质量和材料。

本项目还有一个同等重要的学习目标：使用 DaysLite 跑通个人开发者从工程创建、真机调试、签名、归档、TestFlight、App Store Connect 配置、审核到发布的完整流程，并沉淀一套能用于后续项目的发布手册和进度记录。

## 2. 已确认的产品约束

- 使用 SwiftUI 原生开发，不引入第三方依赖。
- 最低支持 iOS 17，使用 Xcode 26 和 iOS 26 SDK 构建提交版本。
- iOS 与 Android 各自维护界面与本地数据，不进行跨平台同步或迁移。
- 保留 DaysLite 的名称、配色和轻量定位，同时使用 iOS 原生导航、表单、日期选择器和确认弹窗。
- 以个人 Apple Developer Program 会员身份发布；App Store 销售方显示开发者的法定姓名。
- 不使用账号、广告、分析、追踪、推送通知或敏感权限。
- Apple Developer Program 已完成 99 美元付款，目前等待 Apple 激活会员资格；该状态不阻塞本地开发。

## 3. 功能范围

iOS 首版包含与 Android 版相同的功能：

- 创建倒计时事件。
- 默认目标日期为明天。
- 编辑或删除已有事件。
- 事件字段包括名称、目标日期、六种预设颜色、可选备注和每年重复开关。
- 显示剩余天数、今天和已过天数。
- 每年重复事件自动计算下一次出现日期。
- 按事件的实际展示日期升序排列。
- 在应用内手动切换中文和英文。
- 显示本地存储说明、版本号和隐私政策。
- 所有用户数据只保存在当前设备。

首版明确不包含：

- Android 与 iOS 数据迁移或同步。
- iCloud、账号登录或服务端。
- 通知提醒、小组件、应用内购买和广告。
- 第三方分析、崩溃收集或其他 SDK。
- iPad 专用多栏布局。应用可以在兼容的 iPad 模式运行，但首版按 iPhone 体验设计和验收。

## 4. 工程结构

在现有仓库中新建以下目录，不修改 Android 应用的构建和发布流程：

```text
ios/
  DaysLite/
    DaysLite.xcodeproj
    DaysLite/
      App/
      Models/
      Services/
      Views/
      Resources/
    DaysLiteTests/
    StoreAssets/
    docs/
      progress.md
      publishing-playbook.md
      app-store-checklist.md
```

主要组件：

- `DaysLiteApp`：SwiftUI 应用入口，创建并注入数据仓库和应用设置。
- `CountdownEvent`：可编码的事件模型，包含 `id`、`title`、`targetDate`、`note`、`color`、`repeatYearly`、`createdAt` 和 `updatedAt`。
- `CountdownCalculator`：封装展示日期、天数标签、过去状态、摘要和排序所需计算。
- `CountdownStore`：负责从本地读取和保存事件。
- `AppSettings`：负责应用内语言设置。
- `HomeView`：主页、摘要、空状态和事件卡片列表。
- `CountdownEditorView`：新增和编辑表单。
- `SettingsView`：语言、本地存储说明、版本号和隐私入口。
- `PrivacyPolicyView`：显示随应用发布的隐私政策文本。

Bundle ID 初始使用 `com.dayslite.countdown.ios`。在创建 App Store Connect 记录前检查其可用性；如不可用，只修改标识符，不改变商店展示名称 `DaysLite`。

## 5. 界面与交互

应用使用 `NavigationStack` 组织页面。

主页保留现有浅灰背景、白色圆角卡片、蓝色主按钮和事件强调色。顶部显示 DaysLite 与即将到来的事件摘要，并提供原生设置入口。空列表显示引导文案和新增按钮；非空列表按展示日期排序，点击卡片进入编辑页。

新增和编辑页使用 SwiftUI 原生表单控件：名称输入、日期选择、六种颜色、备注文本框和年度重复开关。名称为空时不保存，并在当前页面提供明确提示。编辑已有事件时提供删除操作，删除前显示系统确认弹窗。

设置页显示隐私政策、本地存储说明、语言和版本。语言由用户在应用内主动切换，切换后当前可见页面立即更新。首版支持中文和英文。

应用支持动态字体和 VoiceOver 标签，并检查系统深色模式下的文字对比度。品牌视觉以浅色为主，但不得依赖固定浅色文字导致深色系统下不可读。

## 6. 数据与日期规则

数据流为：

```text
SwiftUI View -> CountdownStore -> JSON -> UserDefaults
             -> CountdownCalculator -> Display State
```

`CountdownStore` 使用 `Codable` 把事件数组编码为 JSON `Data` 后写入 UserDefaults。新增、修改和删除后立即保存。语言设置使用独立键保存。

读取策略强调可恢复性：

- 整体数据不存在时返回空数组。
- 整体 JSON 无法解码时返回空数组并记录调试日志，不让应用崩溃。
- 数据格式需要支持逐条恢复：有效事件保留，损坏事件跳过。
- 模型新增字段时使用默认值或自定义解码保持向后兼容。

所有倒计时按用户当前日历的本地日期计算，不把日期转换为 UTC 时间点。天数计算使用日历的日期边界，避免时区和夏令时造成偏差。

每年重复事件取目标日期的月和日，生成今天所在年份的日期；如果已经过去，则使用下一年。对于 2 月 29 日，非闰年采用 2 月 28 日作为当年展示日期，使事件每年都有明确结果。该规则在界面行为和测试中保持一致。

## 7. 隐私与审核准备

应用不收集、不传输、不共享用户数据，不包含第三方 SDK，也不申请敏感权限。App Store Connect 的 App Privacy 选择“不收集数据”。

应用内隐私政策使用随包发布的本地内容，避免审核或用户查看时受网络状态影响。App Store Connect 使用公开可访问的隐私政策 URL；现有政策需要增加 iOS 删除方式描述，并移除仅适用于 Android 系统设置的表述。

发布材料包括：

- 中英文应用名称、字幕、描述、关键词和版本说明。
- 隐私政策 URL、支持 URL 和联系邮箱。
- iPhone 商店截图，至少覆盖主页、事件列表、编辑页、设置和隐私说明。
- 1024×1024 App Store 图标以及 Xcode 所需图标资源。
- 年龄分级、App Privacy 和审核备注建议答案。

应用功能足以构成独立的原生工具，不使用网页壳。审核版本必须无占位文本、无无效链接并通过真机验证。

## 8. 错误处理

- 名称为空：留在编辑页并显示本地化提示。
- 数据读取损坏：保留可解析记录，跳过损坏记录；完全无法解析时展示空状态。
- 数据写入失败：保留当前内存状态，显示非阻塞错误提示，并允许用户重试保存。
- 隐私网页不可用：应用内置政策仍可查看；公开 URL 在提交前单独验证。
- 签名或上传失败：保存完整错误、环境信息和处理步骤到进度记录，再进行修复和复验。
- 会员未激活：继续本地开发和模拟器验证；将真机长期签名、App Store Connect 和 TestFlight 标记为阻塞。

## 9. 测试与验收

### 单元测试

- 今天、未来一天、多天和过去日期。
- 中英文单复数与日期格式。
- 年度重复事件在今年尚未发生、已经发生和当天发生。
- 2 月 29 日在闰年和非闰年的约定行为。
- 展示日期排序。
- 事件编码、解码、缺失字段和损坏记录恢复。
- 语言设置保存与恢复。

### 模拟器测试

- iOS 17 和当前 iOS SDK 对应运行时。
- 至少一种标准尺寸和一种大屏 iPhone。
- 中文、英文、动态字体、VoiceOver、浅色与深色系统外观。
- 新增、编辑、删除、重启后数据保留和语言切换。

### 真机与发布测试

- 使用开发者 Apple Account 自动签名并在真机安装。
- Release 配置构建和 Archive 成功。
- Xcode Organizer 验证通过。
- 上传 TestFlight 后在真机完成一次安装和核心流程测试。
- App Store Connect 元数据、隐私、年龄分级、截图、支持和隐私链接均完整。
- 提交审核前使用清单完成最终复核。

## 10. 学习与进度记录

`ios/DaysLite/docs/progress.md` 是项目状态的唯一主记录，每个阶段包含：状态、完成时间、负责人、验证证据、阻塞项和下一步。状态使用 `未开始`、`进行中`、`阻塞`、`已完成` 四种值。

`publishing-playbook.md` 记录可复用知识，包括 Apple Account 与 Developer Program、Team ID、Bundle ID、签名证书、描述文件、版本号、Archive、TestFlight、App Store Connect、隐私申报、年龄分级、审核和发布。

`app-store-checklist.md` 提供逐项执行清单。每个需要用户亲自操作的步骤明确标注，尤其是身份验证、协议确认、付款、App Store Connect 法律声明和最终提交。

里程碑如下：

1. 设计与实施计划完成。
2. iOS 工程和核心模型建立。
3. 功能与界面完成。
4. 自动化测试与模拟器验收完成。
5. Apple Developer Program 激活和真机签名完成。
6. Release Archive 与 TestFlight 完成。
7. 商店材料与 App Store Connect 配置完成。
8. 提交审核。
9. 审核通过并发布。
10. 上架流程复盘和手册定稿。

## 11. 完成标准

项目只有同时满足以下条件才视为完成：

- iOS 版实现本规格的全部首版功能。
- 自动化测试通过，并完成模拟器和真机核心流程验证。
- Release Archive 可成功验证并上传。
- TestFlight 安装和验收完成。
- App Store 元数据、隐私和截图材料齐全。
- App 已提交审核并最终在 App Store 发布。
- 发布手册记录了实际过程、问题和解决方案，足以支持后续项目复用。
